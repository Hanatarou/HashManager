how.body=ALGORITHMS\nCRC-16, CRC-32, Adler-32, xxHash3-64, MD5, SHA-1, RIPEMD-160, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/256, SHA3-224, SHA3-256, SHA3-384, SHA3-512, BLAKE2b, BLAKE2s, BLAKE3, Whirlpool. File, Folder, Text and Compare (files) let you tick several; Disks and Compare (folders) use exactly one; Verify checksums takes the algorithm from each line of the file; Duplicates uses BLAKE3 only to tell whether files are identical.\n\nONE READ, MANY HASHES\nEach file is read once, however many algorithms are ticked. Every algorithm runs on its own thread and reading overlaps with hashing, so several hashes cost about as much as the slowest one. Folder, Verify and Duplicates also hash several files at the same time (Options > Hash several files at once; turn it off for a hard disk).\n\nHYPER-THREADING\nIt is a BIOS/UEFI setting and cannot be switched from a program. Options > Use Hyper-Threading threads only limits how many hashing threads run at once: off = at most one per physical core. The status bar shows the cores, threads and whether Hyper-Threading is on.\n\nFILE\nChoose or drop a file. Paste the hash you expect (or use Paste from clipboard): it is compared with every computed hash, and if its length matches no ticked algorithm the program says which one to tick. Entropy (8 = random or compressed data) and the Zstandard ratio are optional.\n\nFOLDER\nHashes every file, with subfolders if ticked. Symbolic links are skipped. Save a checksum file (one line per file, 'hash *path', paths with /; for CRC-32 a real .sfv). With several algorithms ticked, choose which one the checksum file uses.\n\nTEXT\nWhole text, line by line (empty lines skipped) or Base64 (the decoded bytes are hashed). The text is hashed as UTF-8, exactly as typed.\n\nCOMPARE\nTwo files: all selected hashes must be equal. Two folders: files are matched by relative path and reported as Same, Different, Only in A or Only in B.\n\nVERIFY CHECKSUMS\nReads .sha256, .md5, .sfv, SHA256SUMS and similar (GNU 'hash *file', BSD 'SHA256 (file) = hash' and SFV). Paths are relative to the checksum file; a path written with \\ is also found on Linux and macOS. When a line does not say its algorithm, the name of the checksum file is used (.b3, B3SUMS, .sha3, SHA512SUMS...) and only then the length of the hash. Results: OK, MISMATCH, MISSING or SKIPPED.\n\nDUPLICATES\nFiles are grouped by size first, then only the ones that share a size are hashed. Empty files are ignored, and so are hard links to the same data. Deleting is permanent (not the trash), starts with nothing marked, and the program refuses to delete every copy of a file.\n\nDISKS\nLists each disk with its model, size, type (SSD, hard disk, NVMe, USB...), whether it is removable and its volumes. Reading a disk needs administrator rights (Windows) or root (Linux, macOS); disks are only read, never written, and the whole disk is hashed, including space that holds no files.\n\nLANGUAGE\nFile > Language. The 20 most spoken languages; the choice is saved in HashManager.ini. Arabic and Urdu are written from right to left. File > Decimal separator. Follow the system, Point (1.5), Comma (1,5).\n\nSETTINGS AND LOGS\nSaved when the program closes, in HashManager.ini next to the program (portable: no installer, nothing written elsewhere). Each run writes a log, log\\HashManager_<start time>.log, in the same folder (File > Open log folder); the 30 most recent are kept. A damaged settings file falls back to the defaults.

how.body2=NEW ALGORITHMS AND INPUT\nCRC-16, Adler-32, RIPEMD-160, SHA-224, SHA-512/256, SHA3-224/384/512, BLAKE2s and Whirlpool were added. A pasted hash may be hexadecimal or Base64 (Options > Show hashes as). When its length fits several algorithms, the most common is tried first and all candidates are checked in one read.\n\nHMAC, FIND BY HASH, SIGNATURE\nHMAC: a hash with a secret key. Find by hash: lists the files of a folder that have a given hash. Signature: checks minisign and OpenPGP (.asc, .sig) signatures with the publisher's public key; only a signature proves who published a file.\n\nDISK IMAGES\nDisks > Hash a disk image file: .dd .img .raw .iso, split .001, .vhd and .E01. The hash is of the disk inside; for E01 the hashes stored in the image are compared. VHDX, VMDK, QCOW2 and VDI are recognised but not decoded: the container file is hashed.\n\nEXPORT\nExport (Ctrl+E) on any tab. The extension decides: .json, .html (one self-contained page, also a verification report) or .xml (DFXML).\n\nSEVERAL ITEMS, PAUSE\nDrop several files or folders at once: one job, one table. Pause/Resume (Ctrl+P) does not count the paused time in the speed.\n\nSHORTCUTS\nF5 run again, Ctrl+O open, Ctrl+E export, Ctrl+F filter or Find, Ctrl+N clear, Ctrl+P pause, Esc cancel, Ctrl+1 to 9 and 0 switch tabs.\n\nWINDOWS\nFile dates and attributes are shown; NTFS alternate data streams are listed and, if ticked in Options, hashed.
