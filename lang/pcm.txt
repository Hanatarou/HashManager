how.body=ALGORITHMS\nCRC-16, CRC-32, Adler-32, xxHash3-64, MD5, SHA-1, RIPEMD-160, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/256, SHA3-224, SHA3-256, SHA3-384, SHA3-512, BLAKE2b, BLAKE2s, BLAKE3, Whirlpool. File, Folder, Text and Compare (files) dey allow you tick plenty; Disks and Compare (folders) dey use exactly one; Verify checksum dey take the algorithm from each line of the file; Duplicates dey use BLAKE3 just to know if the files be the same.\n\nONE READ, PLENTY HASH\nDem dey read each file one time only, no matter how many algorithm you tick. Each algorithm dey run for its own thread and the reading dey overlap with the calculating, so plenty hash cost almost the same as the slowest one. Folder, Verify and Duplicates dey also calculate plenty file together (Options > Calculate plenty file at the same time; off am for hard disk).\n\nHYPER-THREADING\nNa BIOS/UEFI setting and program no fit change am. Options > Use Hyper-Threading thread dem just dey limit how many hash thread dey work together: off = one at most for each real core. The status bar dey show the cores, the threads and if Hyper-Threading dey on.\n\nFILE\nChoose or drop file. Paste the hash wey you dey expect (or use Paste from clipboard): dem go compare am with every hash wey dem calculate, and if the length no match any algorithm wey you tick, the program go tell you which one to tick. Entropy (8 = random or compressed data) and the Zstandard ratio na optional.\n\nFOLDER\nE dey calculate all file, with sub-folder if you tick am. Dem dey skip symlink. Save checksum file (one line for each file, 'hash *path', path dem with /; for CRC-32 na real .sfv). If you tick plenty algorithm, choose which one the checksum file go use.\n\nTEXT\nWhole text, line by line (dem dey skip empty line) or Base64 (na the decoded bytes dem go hash). Dem dey process text as UTF-8, exactly as you type am.\n\nCOMPARE\nTwo file: all the hash wey you select must equal. Two folder: dem dey match file by relative path and report am as Same, Different, Only for A or Only for B.\n\nVERIFY CHECKSUM\nE dey read .sha256, .md5, .sfv, SHA256SUMS and the likes (GNU 'hash *file', BSD 'SHA256 (file) = hash' and SFV). Path dem dey relative to the checksum file; path wey dem write with \\ dem go still find am for Linux and macOS. If line no talk im algorithm, dem go use the checksum file name (.b3, B3SUMS, .sha3, SHA512SUMS...) and only after that the hash length. Results: OK, NO MATCH, E MISS or DEM SKIP AM.\n\nDUPLICATES\nDem dey group file by size first; na only the ones wey get the same size dem dey hash. Dem dey ignore empty file, and hard link to the same data. Delete na for good (no recycle bin), e dey start with nothing marked, and the program no go gree delete all copy of one file.\n\nDISKS\nE dey list every disk with model, size, type (SSD, hard disk, NVMe, USB...), if e removable and im volumes. To read disk need administrator rights (Windows) or root (Linux, macOS); dem dey only read disk, dem no dey ever write am, and dem dey process the whole disk, even the space wey no get file.\n\nLANGUAGE\nFile > Language. The 20 languages wey pass for speakers; dem dey save your choice for HashManager.ini. Dem dey write Arabic and Urdu from right to left. File > Decimal separator. Follow di system, Dot (1.5), Comma (1,5).\n\nSETTINGS AND LOGS\nDem dey save am when you close the program, for HashManager.ini beside the program (portable: no installer, nothing dey write for another place). Every run dey write one log, log\\HashManager_<start time>.log, for the same folder (File > Open log folder); dem dey keep the newest 30. Settings file wey spoil go go back to default.
